# Stage 6 — Native Android and iOS clients

**Status: phone and tablet clients implemented, with physical-device and distribution acceptance pending.** The [native apps](../apps/mobile/README.md) reuse the existing Web feature set. Tablet windows have a two-pane workspace at wider sizes and share the phone navigation in narrow windows. The real-device milestone is two physical phones joining the same self-hosted server as separate guests and talking to each other.

## First mobile release scope

- Connect to a community by its HTTPS address, join with a nickname and invitation when required, remember servers, and restore each server's guest identity after relaunch. A new device joins independently. Design credential transfer and recovery separately before offering them.
- Browse categories and channels. Read, send, edit and delete own messages, load older history, and reconcile updates after reconnect. Honor archive and role rules from the server.
- Join and leave voice channels, start muted, mute or deafen, show participants and connection state, and resume an eligible call after a short interruption. Verify foreground operation first, then an already active call during app switching, device locking and audio interruptions.
- Ship Polish and English copy and test accessibility on phone layouts first. Initial installation setup stays in Web. Native staff sign-in and the existing channel, invitation, retention and moderation actions use the same server APIs. Push notifications, incoming calls when the app is closed, and public store distribution sit outside the initial phone scope.

## Implemented client boundaries

| Layer                              | Implementation                                                                                                                                                                                                              |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Shared Kotlin Multiplatform module | Versioned HTTP/JSON, event WebSocket and reconnect state, session orchestration, channel catalog and message reconciliation. Uses Ktor with OkHttp on Android and Darwin on iOS. Shared tests cover API and event behavior. |
| Android                            | Kotlin and Jetpack Compose, with Keystore-backed credential storage, the native LiveKit Android SDK, and platform audio and lifecycle APIs.                                                                                 |
| iOS and iPadOS                     | Swift and SwiftUI, with the shared Kotlin framework linked in Xcode, Keychain for credentials, and the LiveKit Swift SDK and Apple audio session APIs.                                                                      |
| Existing server                    | Go remains authoritative for community state, permissions, and voice admission. Better Auth owns staff accounts. Application events and media signaling use separate connections. Both SDKs signal through Go.              |

Credentials and sessions are scoped by canonical server origin. Android and Apple SDKs use bearer media signaling. Application events use a ticket and the installation Origin. See the [HTTP and event contracts](contracts.md) and [identity boundaries](architecture.md#identity-and-authorization).

Stage 7 shares Swift presentation and audio code with the Apple mobile target. Its Swift transport and session logic build independently of the mobile Kotlin framework.

## Work sequence

The [mobile verification record](evidence/stage-6-mobile.md) tracks implementation results and open physical-device checks. The original milestones below define acceptance for the stage.

| Milestone                       | Work                                                                                                                                                                                                                                                                                                                                                                                                                  | Exit check                                                                                                                                                                             |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Toolchain and device proof   | Identify the available Android phone and iPhone, target OS range, and development signing setup. Pin Kotlin, Gradle, Android tooling, Xcode and both LiveKit SDKs once a compatible set is confirmed. Build minimal clients that connect, admit a guest, read the catalog, and join a muted foreground call. Decide the staff sign-in scope and record how microphone permission and signaling work on each platform. | A clean checkout builds both prototypes. Two physical phones on the same server speak and hear each other through the normal Go signaling route.                                       |
| 2. Session and chat             | Add the server chooser, per-server credential restore, guest form, channel list, timeline, older pages, editing and deletion. Implement event-driven reconciliation and safe retry with the original request ID. Use the same shared client state from both native interfaces.                                                                                                                                        | Relaunch preserves the participant ID. A Web peer and each phone converge on the same timeline after sends, edits, deletes and network recovery, with one committed message per retry. |
| 3. Voice and lifecycle          | Add voice controls and a persistent active-call surface. Test microphone denial and recovery, route changes including Bluetooth, foreground-to-background transitions, device lock, interruptions and Wi-Fi/cellular switching. Check revocation and cleanup when leaving or switching servers.                                                                                                                       | A real Android phone and iPhone pass the voice matrix, with accurate microphone state and no duplicate voice session after reconnect.                                                  |
| 4. Private build and acceptance | Review Polish and English, VoiceOver and TalkBack, and phone/tablet layouts. Prepare installable signed Android and iOS builds for the agreed private channel and exercise an update over a prior test build.                                                                                                                                                                                                         | A tester can install, join, chat, call, and update using the published private instructions. Record supported versions, device evidence, and known limits.                             |

Android background calls must account for the microphone foreground service and its while-in-use permission restrictions. On iOS, verify background audio, route handling and interruptions through the app's audio session. Start with an explicitly joined call on each platform. Confirm that relaunch and reconnect never start an unexpected microphone capture.
