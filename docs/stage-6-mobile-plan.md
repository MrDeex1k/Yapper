# Stage 6 — Native Android and iOS clients

**Status: phone and tablet clients in development.** The [native apps](../apps/mobile/README.md) reuse the existing Web feature set. Tablet windows have a two-pane workspace at wider sizes and share the phone navigation in narrow windows. The real-device milestone is two physical phones joining the same self-hosted server as separate guests and talking to each other.

## First mobile release scope

- Connect to a community by its HTTPS address, join with a nickname and invitation when required, remember servers, and restore each server's guest identity after relaunch. A new device joins independently. Design credential transfer and recovery separately before offering them.
- Browse categories and channels. Read, send, edit and delete own messages, load older history, and reconcile updates after reconnect. Honor archive and role rules from the server.
- Join and leave voice channels, start muted, mute or deafen, show participants and connection state, and resume an eligible call after a short interruption. Verify foreground operation first, then an already active call during app switching, device locking and audio interruptions.
- Ship Polish and English copy and test accessibility on phone layouts first. Initial installation setup stays in Web. Native staff sign-in and the existing channel, invitation, retention and moderation actions use the same server APIs. Push notifications, incoming calls when the app is closed, and public store distribution sit outside the initial phone scope.

## Technical boundaries

| Layer                              | Proposed implementation                                                                                                                                                                                                                                  |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Shared Kotlin Multiplatform module | Versioned HTTP/JSON, event WebSocket and reconnect state, session orchestration, channel catalog and message reconciliation. Evaluate Ktor with OkHttp on Android and Darwin on iOS. Check wire models against the existing OpenAPI and event contracts. |
| Android                            | Kotlin and Jetpack Compose. Use Keystore-backed credential storage, the native LiveKit Android SDK, and platform audio and lifecycle APIs.                                                                                                               |
| iOS and iPadOS                     | Swift and SwiftUI. Integrate the shared Kotlin framework in Xcode, use Keychain for credentials, and use the native LiveKit Swift SDK and Apple audio session APIs.                                                                                      |
| Existing server                    | Go remains authoritative for community state, permissions, and voice admission. Better Auth owns staff accounts. Keep application events and LiveKit media signaling separate, and verify both SDKs against Yapper's Go signaling endpoint.              |

Match the [HTTP and event contracts](contracts.md) and the [existing identity and signaling boundaries](architecture.md#identity-and-authorization). Scope credentials and saved sessions by canonical server origin. Keep trusted TLS and origin validation in effect. Prove what each native SDK can send to the signaling endpoint during the first milestone, including the headers the gateway expects. If a bridge or contract adjustment is necessary, document the decision and demonstrate Web and GPUI compatibility before proceeding.

Design the Swift-facing shared API and Apple-specific adapters so the macOS work can evaluate reuse later. Stage 7 will decide which code to share and which macOS versions to support.

## Work sequence

| 1. Toolchain and device proof   | Identify the available Android phone and iPhone, target OS range, and development signing setup. Pin Kotlin, Gradle, Android tooling, Xcode and both LiveKit SDKs once a compatible set is confirmed. | 2. Session and chat             | Add the server chooser, per-server credential restore, guest form, channel list, timeline, older pages, editing and deletion. Implement event-driven reconciliation and safe retry with the original request ID. Use the same shared client state from both native interfaces.                                                                                                                                        | Relaunch preserves the participant ID. A Web peer and each phone converge on the same timeline after sends, edits, deletes and network recovery, with one committed message per retry. |
| 3. Voice and lifecycle          | Add voice controls and a persistent active-call surface. Test microphone denial and recovery, route changes including Bluetooth, foreground-to-background transitions, device lock, interruptions and Wi-Fi/cellular switching. Check revocation and cleanup when leaving or switching servers.                                                                                                                       | A real Android phone and iPhone pass the voice matrix, with accurate microphone state and no duplicate voice session after reconnect.                                                  |
| 4. Private build and acceptance | Review Polish and English, VoiceOver and TalkBack, and phone/tablet layouts. Android background calls must account for the microphone foreground service and its while-in-use permission restrictions. On iOS, verify background audio, route handling and interruptions through the app's audio session. Start with an explicitly joined call on each platform. Confirm that relaunch and reconnect never start an unexpected microphone capture.

## Acceptance

| Surface                   | Evidence to record                                                                                                                                                                                                                                                                                                                                                  |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Shared logic and protocol | Fixture tests for HTTP error mapping, admission modes, credential isolation, event reconciliation, cursor ordering, retry, and rejected or revoked sessions. Run integration checks against a disposable Yapper server.                                                                                                                                             |
| Native interface          | Test invite entry, switching servers, keyboard and screen-reader navigation, Polish and English, and chat layout on supported phone and tablet sizes.                                                                                                                                                                                                               |
| Real-device voice         | Test Android ↔ iOS and each phone ↔ Web on the same installation. Cover microphone permission, mute/deafen, speaker and Bluetooth routes, foreground/background transitions, lock, network changes, moderation initiated from a supported client, and TURN/TLS fallback. Simulators and emulators cover development and UI checks. Use physical devices for audio quality, Bluetooth, cellular, screen-lock and interruption evidence. Record source revision, toolchain and server version, steps, observed results, and any platform limits in a linked evidence report.
