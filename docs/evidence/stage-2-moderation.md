# Stage 2 moderation evidence

Local verification on 2026-11-21 used the moderation revision on `feat/stage-2-community` on macOS arm64 and disposable OrbStack Linux containers. Versions were Go 1.27.4, Node 26.13.1, Bun 1.4.5, Better Auth 1.7.27, PostgreSQL 19, LiveKit 1.13.11, Caddy 2.11.9, HAProxy 3.4.8 and Electron 45.4.1.

| Scenario               | Observed result                                                                                                                                                                                                                                                                                                                                                              |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Migration and roles    | PostgreSQL preserved established guest and account identities. Real Better Auth username login worked; provisioning retries preserved the ID and produced one audit entry. Guests could not provision or read moderation records. Moderators could not act against the owner or grant privileges.                                                                            |
| Live membership        | A moderator's existing WebSocket received role invalidation on demotion and restoration. The same JWT immediately lost access to staff resources after demotion. Kick closed the guest WebSocket with code `4001`, invalidated an outstanding ticket, and allowed a fresh ticket. An identity ban refused old credentials, sends, and admission with the banned cookie.      |
| Guest IP blocking      | Caddy overwrote a caller-supplied address header. Staff could block the shared source address for existing and new guests. The repository integration exercised removal of a guest voice grant at the blocked address. Signed-in staff retained access, and unban released the associated block.                                                                             |
| HTTPS and TURN         | The shared HAProxy/Caddy route preserved the client peer address. The isolated TURN test verified certificate rejection, authenticated relay traffic, and the restricted peer policy.                                                                                                                                                                                        |
| Forced microphone mute | The real self-hosted LiveKit accepted an unmuted signaling publication request. Go removed the active identity on forced mute and refused replay of the prior grant. A new grant could subscribe; LiveKit denied its microphone publication request. Lifting the mute allowed publishing on the next join. The same run checked active voice removal after channel archival. |
| Durability and clients | The isolated container smoke verified setup, invitations, channels, moderation, JWT revocation and data persistence across restart. The existing native macOS Electron smoke verified guest join, renderer isolation and session restore.                                                                                                                                    |

The repository check covers Bun formatting, Oxlint with the shadcn plugin, OpenAPI generation consistency, type checking, package tests and builds. The local integration ran the AUTH service and Go's race-enabled tests against the real PostgreSQL/LiveKit fixtures. React Doctor reported 100/100 for the changed React files.

Forced mute and its removal end the active voice session. Participants can rejoin to listen or speak with the current permissions, and the client displays forced-mute status in English and Polish. Optional IP blocks apply to guests sharing the target's last observed address. A guest can recreate an identity after discarding its credential, subject to the current admission rules and address block.

Manual responsive, keyboard and two-device audio checks on public networks remain pending. The Windows and Linux GPUI integration is a separate Stage 2 work item, and message deletion is part of the message-lifecycle work item.
